# 夕食献立プランナー

栄養バランス・食材の使い切り・残っている食材をまとめて考えて、**複数日分の夕食の献立**を作る Web アプリです。
スマホのホーム画面に追加すればアプリとして使えます（PWA、オフライン対応）。サーバーやアカウントは不要で、データは端末のブラウザ内に保存されます。

## できること

| 要求 | 実装 |
| --- | --- |
| 任意の日付分の献立 | 開始日〜終了日（1〜31日）を指定。1日ごとに 主菜・副菜・汁物・ご飯の量 を提案 |
| 食材の余りを減らす | 食材を**パック単位**（例: 豚こま300g、玉ねぎ3個袋）で買う前提で、余りや期限切れが最小になる組み合わせを探索。買い物の頻度（2日ごと〜期間中1回）も考慮 |
| 栄養素（P/F/C）の目標 | 1人・1食あたりの たんぱく質・脂質・炭水化物 を入力。日ごと・期間合計の両方を目標に合わせ、ご飯の量を日ごとに自動調整 |
| 残っている食材を使う | 入力した食材は優先して使い切るよう献立を構成し、使い切り状況を表示 |
| 備考欄 | 自由記述を解釈して反映（下記）。解釈した内容は画面にチップで表示 |
| 1週間のレビュー | 週の P/F/C 合計と目標の比較、日ごとのエネルギー内訳グラフ、エネルギー比・野菜量・たんぱく源の内訳、自動コメント。「作った／作らなかった」「★評価」「メモ」を記録でき、評価は次回以降の献立に反映 |

そのほか

- 料理はプルダウンで手動変更でき、栄養と買い物リストがすぐ再計算されます。🔒 で固定した日は「別の案を作る」でも残ります。
- 買い物リストは買い物の回ごと・売り場（カテゴリ）ごとにまとめ、チェックできます。冷凍保存が必要な食材には注意書きが付きます。
- 期間終了時の残り見込みを、ワンタップで次の期間の「残っている食材」に引き継げます。
- データの書き出し／読み込み（JSON）。

### 備考欄で読み取れる書き方の例

- `魚多め` / `鶏肉が好き` / `カレーが食べたい` / `和食中心` → 優先
- `卵アレルギー` / `ピーマン嫌い` / `辛いものは苦手` / `牛肉はダメ` → 使わない
- `揚げ物は控えめ` → 減らす
- `魚は週3回` → 回数の目安
- `30分以内` / `時短` → 主菜・副菜の調理時間の上限
- `汁物なし` / `副菜なし` / `ご飯なし`

読み取れなかった部分は画面に表示されます。

## 使い方

### 手元で開く

```bash
npm start          # = python3 -m http.server 8000
# ブラウザで http://localhost:8000 を開く
```

`index.html` を直接ダブルクリックしても動きます（その場合は計算中に画面が一瞬止まることがあります）。

### スマホでアプリとして使う

GitHub Pages などの HTTPS で公開し、スマホのブラウザで開いて「ホーム画面に追加」してください。
（GitHub のリポジトリ設定 → Pages → Branch を選ぶだけで公開できます）

## 仕組み

- `js/data.js` … 食材（栄養値は日本食品標準成分表（八訂）を参考にした概算、パックの量、保存日数）とレシピ（主菜31・副菜24・汁物12）
- `js/notes.js` … 備考欄の解釈
- `js/planner.js` … 献立の最適化。焼きなまし法で「栄養のずれ・食材の余りと期限切れ・在庫の使い残し・同じ料理の繰り返し・備考や評価」を合計したスコアを最小化
- `js/review.js` … 週間レビューの集計とコメント
- `js/app.js` … 画面

テスト:

```bash
npm test
```

## 注意

- 栄養値は概算です。医療上の食事制限がある場合は専門家の指示を優先してください。
- アレルギーの除外は登録されている食材名・カテゴリにもとづきます。加工品・調味料に含まれる原材料までは完全には判定できません。
